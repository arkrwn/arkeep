# mikvault Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build mikvault — a standalone, dependency-free Rust secrets vault (core lib + daemon + CLI) that runs on Linux and macOS, using envelope encryption with host-sealed and root-sealed DEK wrapping, per-service ACL tokens, and audit logging.

**Architecture:** Three-crate workspace (`mikvault-core` crypto/format/ACL lib with zero process I/O beyond disk reads, `mikvaultd` daemon serving a local Unix socket with platform-specific key sealing, `mikvault-cli` admin binary talking to the daemon's socket). `HostSeal` trait isolates the one platform-dependent piece (systemd-creds on Linux, Keychain/Secure Enclave on macOS) so core logic and its tests are platform-agnostic.

**Tech Stack:** Rust (edition 2021, MSRV 1.75), `aes-gcm-siv` (DEK/entry AEAD), `x25519-dalek` (root keypair + ECIES wrap), `zeroize` (key material cleanup), `serde` + `bincode` (vault.mika binary format), `serde_json` (socket protocol + meta.json), `clap` (CLI), `security-framework` (macOS Keychain, `cfg(target_os = "macos")` only), `rand` (`OsRng`), std `UnixListener`/`UnixStream` (no async runtime). GitHub Actions CI on `ubuntu-latest` and `macos-latest`.

**Spec:** `docs/superpowers/specs/2026-11-09-mikvault-design.md`

## Global Constraints

- Rust edition 2021, MSRV 1.75+, workspace at repo root.
- Platforms: Linux (systemd required) and macOS (Keychain/Secure Enclave via `security-framework`) — no other OS in scope.
- No plaintext secret or key material is ever written to disk, except the one-time root private key printed at `mikvault init --root`, which the operator is responsible for moving off-machine immediately.
- `vault.mika` and `meta.json` never contain plaintext; `meta.json` is non-secret (safe to read without unsealing).
- No AI attribution anywhere — not in commit messages, code comments, README, or any doc.
- License: MIT.
- No dependency on any external vault/KMS service (no network calls to HashiCorp Vault, cloud KMS, etc.).

## Review Focus

- A request for an empty or malformed path (e.g. `""`, `"../etc/passwd"`, no prefix match at all) must be denied by the ACL check, not panic or fall through to "allowed". → Task 4.
- Two services hitting the daemon concurrently must never see each other's decrypted values or corrupt the in-memory store — the daemon needs a single lock around store access, not per-request unsynchronized access. → Task 8.
- A truncated or corrupted `vault.mika` must make `mikvaultd` refuse to start with a clear error, never silently initialize a fresh empty vault over it. → Task 3 and Task 8.
- A sealed host-key blob that's been altered or truncated must fail `unseal()` cleanly (AEAD tag mismatch surfaced as a typed error), never return garbage bytes treated as a valid key. → Task 5 and Task 6.
- `mikvault recover --root-key` run with the wrong private key file, or a missing one, must fail with a clear message and must not write or modify `vault.mika`. → Task 14.
